# 확인됨 (VERIFIED) — Pleos Connect(AAOS) 차량 앱

**차를 남에게 맡긴 순간부터 돌려받을 때까지, 차가 스스로 "제대로 끝났는지"를 판정해 증명해 주는 차량 전용 앱입니다.**

초기 HTML 시안을 Android Automotive OS 네이티브 앱(Kotlin + Jetpack Compose)으로 옮긴 프로젝트입니다.
판정 엔진은 안드로이드 의존성이 없는 순수 Kotlin입니다. JVM 단위·런타임·Pleos 연결·Compose 화면과 휴대폰 알림 전송을 자동 테스트로 검증합니다.

## 차주의 휴대폰으로 알림 받기

1. 차에서 **보낸 알림 → 차주 휴대폰 알림 → 동의하고 연결 시작**을 누릅니다. 설정에서도 같은 화면을 열 수 있습니다.
2. 휴대폰에 **ntfy**를 설치하고 알림을 허용합니다. Android에서는 차의 **연결 QR·주제 보기**를 눌러 QR을 스캔합니다. 직접 입력할 때는 ntfy에서 기본 서버 `ntfy.sh`를 선택하고 차에 표시된 주제 이름을 구독합니다. [ntfy 휴대폰 구독 안내](https://docs.ntfy.sh/subscribe/phone/)
3. 차에서 **시험 알림 보내기**를 누르고 휴대폰 알림창에서 시험 문구를 확인합니다. **보낸 알림**에는 전송 대기, 서버 접수, 실패 상태가 표시됩니다. 서버 접수 후 실제 휴대폰 표시 여부는 휴대폰에서 확인합니다.

차주가 연결한 이후에 생성한 차주용 알림만 전송합니다. 상세 위치와 주행 기록은 차 안에 저장하고, 외부 서버에는 사건 종류를 나타내는 짧은 문장만 보냅니다. 예시 신호로 만든 알림에는 예시 표시가 붙습니다. 인터넷이 끊기면 대기열을 기기에 저장하고 앱이나 감시 서비스가 동작할 때 재시도합니다. 연결 QR과 주제 이름을 아는 사람은 해당 주제에 접근할 수 있습니다. **휴대폰 연결 해제** 후 다시 연결하면 새 주제가 만들어집니다.


## 확인 근거 — 차주가 없는 순간의 증거

차를 남에게 넘긴 순간(① 대리, 맡김, 빌려주기)에는 차주가 차 옆에 없습니다. 그래서 요약이나 점수 대신 **어떤 신호를 언제 읽어 그렇게 판정했는지**를 남깁니다.

- **① 대리 완료·미완료:** 인수 → P단 → 위치(집 반경 Nm, GPS 받은 시각) → 시동 OFF 또는 10초 정지·운전석 하차 → 도착(주행거리·배터리). 차 화면의 '확인 근거'와 알림 기록에서 세부 내용을 봅니다. 연결한 휴대폰에는 결과를 알리는 짧은 문장이 표시됩니다.
- **맡김·빌려준 차 리포트:** 넘김 → 시동 ON/OFF·운전석 문 열림·급감속(각각 시각·출처) → 돌려받음. 최근 20줄까지 남기고(첫 줄 '넘김'은 늘 유지) 앱을 다시 켜도 이어집니다.
- **출처 표시:** `차 신호 HH:MM:SS`(차에서 읽은 시각), `GPS HH:MM:SS`, `지하 진입 전 마지막 GPS`, 실차에서 읽지 못하면 `확인 불가`, 시연이면 `시뮬레이터`. 실차에서 읽지 못한 값(창문·바퀴·문 횟수 등)은 리포트와 알림에서 숫자 대신 '확인 불가'로 씁니다.
- **지금 실차에서 확실히 읽히는 근거:** 기어·시동·차속·GPS(① 대리 완료의 핵심). 착좌는 Android 16 이상, 문·잠금·창문은 Pleos 승인 후.
- 코드: `VerdictEngine.Proof`, `ValetState.proof`, `LendState.proof`, `Signals.seenAt`(CarBridge·PlaceTracker가 읽은 시각을 남김) · 테스트: `ScreensTest.s03`, `MyHyundaiBetterTest.lend_reportKeepsProof_andUnreadSignalsAreNotFacts`


## 현대 기능 연계 (2026-11-09 추가)

- **Pleos SDK 연결:** 현대 Pleos Vehicle SDK 2.3.2(조회 전용)로 문·트렁크·잠금·창문·착석·벨트·엔진오일·워셔액·주행거리·EV 배터리를 읽고, NaviHelper 3.0.5로 현대 내비 목적지·남은 거리·시간을 받습니다(`vehicle/PleosBridge.kt`, `vehicle/PleosNavi.kt`). 공개 저장소 `nexus-playground.pleos.ai`에서 받으며, Pleos가 없는 폰·차에서는 아무것도 하지 않습니다. 경고등·타이어 저압은 `PRIVATE_CAR_SAFETY`(제휴 승인) 권한이 필요해 승인 전에는 "확인 불가"입니다. 실제 동작은 Pleos 에뮬레이터 확인 전입니다.
- **차가 쓰는 인수인계서:** 맡길 때와 돌려받을 때 경고등·타이어·오일·워셔액·문·창문·주행거리·배터리를 기록하고 바뀐 것만 비교합니다(`CarCheck`, `diffChecks`). 못 읽은 항목은 "확인 불가".
- **대리 귀가 내비 연동:** 기사 동의 뒤 현대 내비 목적지를 집으로 요청하고, 차주에게 도착 예정 시각과 경로 이탈(남은 거리가 1.5km 넘게 늘어 60초 유지, [제안값])을 알립니다.
- **현대 기능 맡김 체크리스트:** 맡기기 전 발레 모드·빌트인 캠 주차 녹화·디지털 키 2 공유 기한, 돌려받을 때 빌트인 캠 영상 저장 구간·키 회수·발레 모드 기록 확인. 앱이 이 기능들의 상태를 읽을 수 없으므로 차주 확인으로 기록합니다.
- **정비 맡김 이탈 감지:** 시동 ON과 실제 주행거리 증가 200m 이상이 확인되고, 맡긴 곳에서 GPS 오차 반경을 뺀 거리 1km 이상이 30초 동안 새 GPS 관측으로 이어질 때 한 번 알립니다. 위치 정확도 50m 이내, GPS 수신 간격 15초 이내를 확인하며 신호가 부족하면 이탈을 확정하지 않습니다. 기준값은 실측 전 제안값입니다.
- **대리기사 안내와 기록 범위:** 동의·인수·도착 시각, 주차 전후 차량 상태와 완료 판단 근거를 기록합니다. 대리 이력의 최고속도·급감속·공회전 통계는 수집 대상에서 제외하고, 기존 대리 이력과 진행 상태도 읽을 때 정리합니다. 이력 화면과 CSV에서도 같은 범위를 적용합니다.
- **정차 중 배터리 사용:** 빌려주기·맡김 동안 P단 정차 중 쓴 배터리(V2L·유틸리티 모드·공조 등)를 리포트에 표시.
- **맡김 이력서:** 대리·맡김·빌려주기 기록을 모아 총 횟수, 문제 없이 돌려받은 횟수, 남이 운전한 거리·급감속을 요약하고 CSV로 내보냅니다. 인증중고차 매각·운전습관 보험(UBI) 상담 때 설명 자료로 쓰는 용도이며 공식 인증 자료는 아닙니다.

| 장점 | 구현 |

### 차 권한별로 읽히는 신호

AAOS 권한 정의(`VehiclePropertyIds`, Car 매니페스트) 기준입니다. 실차·에뮬레이터에서 확인한 결과는 아닙니다.

| 구분 | 신호 | 권한 |
|---|---|---|
| 일반 권한 | 기어, 시동, 외기온도, 모델명 | `CAR_POWERTRAIN`, `CAR_EXTERIOR_ENVIRONMENT`, `CAR_INFO` |
| 실행 중 동의 | 차속, 배터리·연료 잔량 | `CAR_SPEED`, `CAR_ENERGY` |
| **Android 16 이상 차**에서만, 실행 중 동의 | 주행거리, 바퀴별 공기압, 조향각, 착좌, 방향지시등 스위치·깜빡이 빛(양쪽이 함께 깜빡이면 비상등으로 봄) | `CAR_MILEAGE_3P`, `CAR_TIRES_3P`, `READ_CAR_STEERING_3P`, `READ_CAR_SEATS`, `READ_CAR_EXTERIOR_LIGHTS` |
| 서명 권한(일반 앱에는 열리지 않음) | 문·트렁크·잠금, 창문, 벨트, 시트 자세·등받이, 공조·열선, 와이퍼, 전조등, 실내등, 크루즈, 비상등 상태 | Pleos Vehicle SDK 전환·승인 후 읽을 계획 `[확인 필요]` |
| 공개 API 없음 | 순정 안전하차보조(SEA) 경고 | 시뮬레이터로만 시연 |
| 아직 구독하지 않음 | 워셔액 부족 | 시뮬레이터로만 시연 |

그래서 Android 16 이전 차에서는 주행거리·공기압·조향각·착좌도 '미지원'이 되고, 서명 권한 신호는 지금 실차에서 읽지 못합니다. 시뮬레이터는 이 신호들을 모두 넣어 시연합니다.

## 빌드

Android Studio(JDK 17 이상)에서 이 폴더를 열면 됩니다. 명령줄에서는 다음과 같습니다.

```bash
./gradlew :app:testDebugUnitTest :app:assembleRelease
```

화면 테스트는 debug 변형에서만 돌아가므로 `test`가 아니라 `testDebugUnitTest`를 씁니다. 결과 APK는 `app/build/outputs/apk/release/app-release.apk`이고 제출용 이름 `확인됨.apk`로 바꿔 씁니다(R8 축소, 공모전용 debug 키 서명). 개발(debug) 빌드에서만 신호 시뮬레이터가 열립니다.

> **한글 경로 주의:** 이 PC는 시스템 코드페이지 문제로 한글 경로에서 단위 테스트 JVM이 클래스를 찾지 못합니다.
> `subst V: "<이 폴더 경로>"`로 가상 드라이브를 만든 뒤 `V:`에서 빌드하세요. APK 빌드는 한글 경로에서도 되도록 `android.overridePathCheck=true`를 켜 두었습니다.

## 지원 차종과 ⑩ 출발 준비

**지원 차종(Pleos Connect 탑재, 2026-11-02 공개 보도 기준):** 더 뉴 그랜저(2026년 5월 출시), 디 올 뉴 아반떼(6월 공개, 3분기 판매), 디 올 뉴 투싼(10월 계약 시작). 첫 실행과 설정에서 고르고, 실차에서는 `INFO_MODEL`로 자동 인식합니다(`CarModel`). 열선·통풍은 트림마다 달라 차량 신호로 지원 여부를 확인합니다.

**⑩ 출발 준비:** 운전자별(차주·배우자) 온도·열선·통풍·핸들 열선·성에 제거 설정을 저장합니다.
- **지금 미리 켜기 / 출발 예약:** 시동이 꺼진 차는 화면도 꺼져 있어, 실행은 마이현대 원격 공조로 넘깁니다(연동 목업). 조건은 P단·문 잠김·탑승자 없음·배터리 20% 이상이고, 10분 뒤 자동으로 꺼집니다([제안값]).
- **탑승 즉시 적용:** 운전석에 앉고 시동이 켜지면 ②가 알아본 운전자의 설정을 적용합니다. 처음 보는 운전자에게는 개인 설정을 적용하지 않고, 차가 지원하지 않는 항목과 빈 좌석 열선은 빼고 적용합니다.
- 공조 제어는 Pleos Vehicle SDK Control 승인 전이라 실차에서는 읽기만 하고, 제어는 `CLIMATE` 플래그와 차종 지원이 모두 있을 때만 합니다.

## 화면 구성

하단 탭은 **홈 · 제어 · 기록 · 더보기** 4개입니다(자세한 배치는 위 '화면 개편').

- **홈:** 차 상태·사진·빠른 제어, 경고와 진행 중 맡김을 목록 맨 위에. 경고(문 열림·하차 후 잠금 해제·벨트 미체결)를 누르면 해당 문·좌석이 강조된 차량 사진 화면으로 이동합니다. 차주 PIN이 필요한 동안에는 인증을 거쳐 같은 위치로 이어집니다.
- **제어:** 위에서 본 차로 잠금·문 상태·좌석·온도를 보고 바꿉니다. 실차 원격 제어는 Pleos 제어 승인 전이라 체험 차량에서만 동작하고, 실차에서는 상태 확인만 합니다. 명령을 보내면 요청 시각과 차 신호로 확인한 결과를 보여 줍니다.
- **기록:** 맡김 이력서, 주행·소모품·주차 위치, 과태료 날짜 대조.
- **더보기:** 차량 관리·드라이빙 인사이트·디지털 키·카라이프(시연용 월렛·샵), 상황별 기능(기능 10개), 보낸 알림·설정. 맨 위 차주 줄은 차량 등록·변경입니다.
- **외관·실내 사진(차량 둘러보기):** 그랜저·아반떼·투싼·아이오닉 3의 현대 공식 사진과 문·좌석별 상태(마지막 수신 시각). 위치별 상태를 읽지 못하면 특정 문·좌석을 추측하지 않고 확인 불가로 남깁니다. 온도·열선은 제어 › 실내에서 바꿉니다.
- **검색:** ‘와이퍼’나 ‘공기압’처럼 운전자가 쓰는 말로 기능을 찾습니다.
- 폰에서는 세로로, 차량 가로 화면은 두 열로 나눕니다. 주행 중에는 조작을 제한하고 속도와 주행 요약만 표시합니다.

## 앱 안 취약점 보강 (2026-11-04)

- **차주 PIN 잠금** (`core/OwnerLock.kt`, `ui/OwnerPinPad.kt`): 설정 진입, 대리 종료 승인, 차 빌려주기, 디지털 키, 제출용 빌드의 시뮬레이터를 PIN으로 막음
  - PIN은 소금 + PBKDF2 해시로만 저장하고, 5번 틀리면 잠금 시간이 두 배씩 늘어남
  - 대리나 차 빌려주기를 시작하면 바로 다시 잠김
- **시뮬레이터 차단:** 실차에 연결되면 제출용 빌드에서 신호 시뮬레이터가 실제 신호를 덮어쓰지 못함
- **외부 요청 방어:** 진행 중인 대리·동행 판정을 다른 앱의 시작 요청이 지우지 못함. Gleo 수신은 1초에 한 번, 입력은 500자까지만 읽음
- **저장 기록:** 저장 기록이 깨지면 기본값으로 켜고 원본은 `_broken`으로 보관. 백업·기기 이전에서 모든 기록을 제외(`data_extraction_rules.xml`)
- **CSV:** 수식으로 시작하는 칸은 앞에 `'`를 붙임. '국세청 서식 기준 CSV'는 공용 다운로드 폴더(MediaStore)에 저장하고, 다운로드에 못 쓰는 차에서는 앱 폴더에 남김. 열은 국세청 「업무용승용차 운행기록부」 서식 기준 `[원문 대조 확인 필요]`, 법인명·사업자등록번호·자동차등록번호는 빈칸
- **저장 기록 암호화** (`Vault.kt`): 저장 기록을 AES-256-GCM으로 암호화하고, 키는 Android Keystore에 둠. Keystore가 없는 PC 테스트에서는 평문
- **PIN 복구 코드:** PIN을 정할 때 12자리 복구 코드를 한 번만 보여 주고, PIN 패드의 "PIN을 잊었어요"로 PIN을 끌 수 있음
- **화면 이동:** 화면을 옮기면 스크롤이 맨 위에서 시작
- **개인 기록 가리기 (2026-11-05):** 대리·빌려주기 중에는 운행기록부, 알림, 인사이트, 차량 관리, 디지털 키, 월렛을 차주 PIN을 넣어야 열 수 있음
- **기록 정리·시간:** 5년이 지난 운행기록을 정리하고, 판정 시간은 부팅 후 경과 시간으로 잼(차 시계 변경에 영향 없음)
- **음성·절전:** 한국어 음성이 없으면 화면 안내로 남김. 실차에서 판정이 없으면 타이머는 10초에 한 번만 깨어남

## 아직 연결 안 된 것 (`[확인 필요]`)

- **위치:** AAOS 표준 위치(`ACCESS_FINE_LOCATION`, 실행 중 동의)로 실제 GPS 판정을 합니다(설정 → 장소 등록). 자동차 OS에서는 집을 등록해야 ①을 시작하고, 첫 위치를 받기 전에는 대리 완료·목적지 밖 하차 판정을 보류합니다. Pleos FusedLocation SDK는 '준비 중'이라 승인 후 `PlaceTracker`만 교체합니다.
- **재부팅 뒤 위치(알려진 한계):** 백그라운드 위치 권한을 쓰지 않아, 차가 다시 켜진 뒤 앱을 한 번 열기 전까지는 감시 서비스가 위치 유형 없이 돌아 위치를 받지 못합니다(Android 14+는 배경에서 위치 유형을 붙이지 못함).
- **Pleos Vehicle SDK:** 라이브러리 저장소 주소가 공개 문서에 없어(Playground 계정 필요) 아직 AAOS 표준 `CarPropertyManager`로 읽습니다. 받으면 `CarBridge`의 읽기 경로를 Vehicle State SDK로 바꿉니다.
- **앰비언트 조명·시트 제어:** Pleos Vehicle SDK의 Control이 '준비 중'이라 `ambientControl`, `seatControl`이 실차에서 꺼져 있습니다.
- **SEA(안전하차보조) 경고 신호:** 서드파티에 공개되지 않아 시뮬레이터로만 넣습니다.
- **블루멤버스 포인트와 마이현대 정비 예약 연결:** 시연용입니다. 차주 휴대폰 알림은 위의 ntfy 구독 절차로 연결합니다.
- **서명 권한 차 신호:** 문·잠금·창문·벨트·시트 자세·공조·와이퍼·전조등·실내등·크루즈·비상등 상태는 서명 권한이라 일반 앱에는 열리지 않습니다. 구독이 실패하면 차종 지원에서 '미지원'이 되고 대체 판정으로 동작합니다. 주행거리·공기압·조향각·착좌·방향지시등 빛(`_3P`, `READ_CAR_SEATS`, `READ_CAR_EXTERIOR_LIGHTS`)은 Android 16 이상 차에서만 실행 중 동의로 열립니다.
- **읽지 못한 신호의 표시:** 일부 화면은 읽지 못한 신호를 '확인 불가'로 쓰지만, 엔진이 보내는 문장과 주행거리·벨트·잠금·운전석 착좌의 차종 지원 표시는 아직 정리하지 않았습니다.
